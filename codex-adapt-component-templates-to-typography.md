# Задание для Codex: адаптация шаблонов компонентов к общей типографике сайта

## Контекст проекта

Проект работает на **1С-Битрикс**. В шаблоне сайта подключён общий файл типографики:

```text
typography-clean.css
```

Файл подключается **после основного `style.css`** и содержит единую адаптивную шкалу размеров, межстрочных интервалов и начертаний.

Основная задача — привести все шаблоны компонентов сайта к этой системе типографики и убрать дублирующие локальные настройки шрифтов.

## Важное правило для H1

На внутренних страницах полноценный `H1` уже находится в баннере страницы.

Не добавлять второй `H1` в шаблоны списков услуг, товаров, новостей, расписания и других разделов.

Не менять существующую структуру баннера без необходимости.

## Цель

Проверить все шаблоны компонентов текущего шаблона сайта и заменить локальные, несогласованные или дублирующиеся типографические настройки на переменные из `typography-clean.css`.

После выполнения:

- все размеры текста должны управляться общей системой;
- локальные CSS-файлы компонентов не должны без необходимости задавать собственные `font-size`, `line-height` и `font-weight`;
- адаптивность должна обеспечиваться преимущественно через `clamp()` и переменные общего файла;
- внешний вид, сетка, цвета, анимации и функциональность компонентов должны сохраниться;
- PHP-логика и параметры компонентов не должны быть нарушены.

# 3. Правила замены размеров

## Основной текст

Для обычного текста использовать:

```css
font-size: var(--font-size-base);
line-height: var(--line-height-body);
```

Не задавать `font-size` обычным `p` и `li`, если они уже наследуют размер от родительского блока или глобальных стилей.

## Мелкий служебный текст

Для дат, подписей, метаданных, номеров карточек, пояснений и юридического текста использовать:

```css
font-size: var(--font-size-xs);
```

или:

```css
font-size: var(--font-size-sm);
```

Выбор зависит от визуальной важности текста.

Не использовать размеры меньше `12px`.

## Увеличенный текст

Для вводных абзацев, подзаголовков раздела и лид-текста использовать:

```css
font-size: var(--font-size-lg);
```

или готовые классы:

```html
<p class="lead">...</p>
<p class="text-lead">...</p>
```

## Заголовки

Предпочитать семантические теги `h1`–`h6` без локального изменения размера.

Если элемент визуально является заголовком, но по структуре не может быть тегом заголовка, использовать соответствующую переменную:

```css
font-size: var(--font-size-h2);
line-height: var(--line-height-heading);
```

Не использовать `h4` для обычного вводного текста или рекламной подписи только ради размера.

## Карточки

Обычный заголовок карточки:

```css
font-size: var(--font-size-card-title);
line-height: var(--line-height-card-title);
font-weight: var(--font-weight-semibold);
```

Крупный акцентный заголовок карточки:

```css
font-size: var(--font-size-card-featured-title);
line-height: var(--line-height-card-featured-title);
```

Заголовок плитки:

```css
font-size: var(--font-size-card-tile-title);
line-height: var(--line-height-card-tile-title);
```

Текст карточки:

```css
font-size: var(--font-size-card-body);
line-height: var(--line-height-card-body);
```

Метаданные карточки:

```css
font-size: var(--font-size-card-meta);
```

## Баннеры

Заголовок главного или внутреннего баннера:

```css
font-size: var(--font-size-hero);
line-height: 1.1;
```

Либо использовать существующие совместимые переменные конкретного шаблона баннера.

Описание баннера:

```css
font-size: var(--font-size-banner-body);
line-height: 1.5;
```

Не создавать дополнительный `H1` под баннером.

## Кнопки

```css
font-size: var(--font-size-button);
line-height: var(--line-height-button);
```

Не менять высоту кнопки только за счёт слишком большого `line-height`.

## Формы

Подписи полей:

```css
font-size: var(--font-size-form-label);
```

Для `input`, `textarea` и `select` на мобильных размер не должен быть меньше `16px`, чтобы iPhone не увеличивал страницу автоматически.

## Подвал

Основной текст подвала:

```css
font-size: var(--font-size-sm);
```

Телефоны и важные контакты:

```css
font-size: var(--font-size-footer-contact);
line-height: var(--line-height-footer-contact);
```

Юридический текст и пояснения:

```css
font-size: var(--font-size-xs);
```

# 4. Что необходимо найти и исправить

Найти в CSS шаблонов следующие случаи:

```css
font-size: 12px;
font-size: 14px;
font-size: 16px;
font-size: 18px;
font-size: 20px;
font-size: 24px;
font-size: 32px;
```

и любые другие фиксированные размеры текста.

Для каждого найденного значения определить назначение элемента и заменить его подходящей переменной.

Также найти:

```css
font-size: ... !important;
line-height: ... !important;
font-weight: ... !important;
```

Удалять `!important`, если каскад можно исправить более точным селектором или правильным порядком подключения файлов.

Найти повторяющиеся медиазапросы, где один и тот же селектор несколько раз получает разные размеры текста.

Объединить такие правила, если это безопасно.

Найти CSS, где одновременно задаются:

```css
font: ...;
font-size: ...;
line-height: ...;
font-weight: ...;
```

Не использовать сокращённое свойство `font`, если оно случайно сбрасывает семейство, начертание или межстрочный интервал.

# 5. Семантика HTML

Проверить HTML-разметку шаблонов компонентов.

## Требования

- На странице должен оставаться один `H1`.
- Для внутренних страниц `H1` уже выводится баннером.
- Названия основных разделов внутри страницы — `H2`.
- Заголовки групп и крупных подразделов — `H3`.
- Заголовки небольших подпунктов — `H4`.
- Названия карточек допустимо выводить через `H3` или `H4` в зависимости от структуры страницы.
- Телефоны, адреса, цены и кнопки не должны размечаться заголовками только ради визуального размера.
- Вводный текст не должен быть `H4`, если он не является заголовком.
- Не менять семантику там, где это может нарушить верстку или работу административного режима Битрикс, без проверки результата.

Сохранять:

- `$this->AddEditAction()`;
- `$this->AddDeleteAction()`;
- `GetEditAreaId()`;
- динамические атрибуты;
- PHP-условия;
- параметры компонентов;
- микроразметку;
- ссылки и обработчики событий.

# 6. Адаптивность

Не добавлять отдельный медиазапрос для каждого компонента только ради изменения размера шрифта.

Сначала использовать адаптивные переменные из `typography.css`.

Локальный медиазапрос допустим только когда:

- текст физически не помещается в конкретную компоновку;
- меняется сама структура блока;
- на мобильном заголовок карточки должен иметь особое ограничение;
- это невозможно решить общей переменной или переносом строк.

При необходимости использовать:

```css
text-wrap: balance;
```

для заголовков и:

```css
text-wrap: pretty;
```

для длинных абзацев.

Не использовать фиксированную высоту текстового блока, если текст может занимать несколько строк.

Не скрывать переполнение текста без явной необходимости.

Если применяется обрезка карточек, она должна быть осознанной и одинаковой для элементов одной сетки.

# 7. Что нельзя менять

Не изменять без необходимости:

- цвета;
- фон;
- тени;
- радиусы;
- размеры изображений;
- сетку;
- расположение блоков;
- hover-анимации;
- JavaScript;
- PHP-логику;
- параметры компонентов;
- названия CSS-классов;
- структуру данных `$arParams` и `$arResult`;
- работу композитного режима и кеширования Битрикс.

Не проводить большой рефакторинг, не связанный с типографикой.

Не удалять переменную из `typography.css`, пока не проверено, что она нигде не используется.

# 8. Порядок выполнения

## Этап 1. Инвентаризация

Составить список всех CSS-файлов шаблонов компонентов.

Для каждого файла определить:

- количество локальных `font-size`;
- количество локальных `line-height`;
- количество локальных `font-weight`;
- наличие `!important`;
- наличие повторяющихся правил в медиазапросах;
- используемые переменные типографики.

## Этап 2. Классификация

Разделить найденные элементы на категории:

- основной текст;
- мелкий текст;
- метаданные;
- заголовки страницы;
- заголовки раздела;
- заголовки карточек;
- текст карточек;
- кнопки;
- формы;
- меню;
- баннеры;
- контакты;
- подвал.

## Этап 3. Замена

Заменить фиксированные значения на подходящие CSS-переменные.

Удалить локальные правила, которые полностью дублируют `typography.css`.

Не удалять правило только потому, что в нём присутствует `font-size`: сохранить остальные свойства селектора.

Пример:

Было:

```css
.service-card__title {
    margin-bottom: 12px;
    font-size: 22px;
    line-height: 1.25;
    font-weight: 600;
    color: var(--primary);
}
```

Стало:

```css
.service-card__title {
    margin-bottom: 12px;
    font-size: var(--font-size-card-title);
    line-height: var(--line-height-card-title);
    font-weight: var(--font-weight-semibold);
    color: var(--primary);
}
```

## Этап 4. Очистка

После замены:

- объединить дублирующиеся селекторы;
- удалить пустые CSS-блоки;
- убрать закомментированные старые размеры, если они больше не нужны;
- убрать повторяющиеся медиазапросы;
- не создавать новые алиасы без реальной необходимости;
- сохранить читаемую структуру файлов.

## Этап 5. Проверка

Проверить шаблоны на ширинах:

```text
1440px
1200px
992px
768px
576px
375px
320px
```

# 10. Критерии готовности

Работа считается выполненной, если:

1. Все шаблоны компонентов проверены.
2. Большинство фиксированных размеров текста заменено переменными.
3. Оставшиеся фиксированные размеры обоснованы особенностями конкретного блока.
4. Нет второго `H1` на внутренних страницах.
5. Размер `H4` не превышает значение из общей шкалы.
6. Обычный текст не размечен заголовками только ради размера.
7. На мобильных нет текста меньше `12px`.
8. Поля формы на телефоне имеют размер не меньше `16px`.
9. Нет новых дублирующихся медиазапросов.
10. Нет горизонтального переполнения из-за длинных заголовков.
11. Длинные названия товаров и услуг корректно переносятся.
12. Подвал не выглядит крупнее основного контента.
13. Баннеры сохраняют существующий внешний вид и `H1`.
14. Административное редактирование компонентов Битрикс продолжает работать.
15. PHP не содержит синтаксических ошибок.
16. В консоли браузера нет новых ошибок.

# 13. Ожидаемый стиль изменений

Изменения должны быть точечными, понятными и безопасными.

Предпочитать:

```css
font-size: var(--font-size-card-title);
```

вместо:

```css
font-size: clamp(...);
```

в каждом отдельном компоненте.

Новые значения `clamp()` добавлять в общий файл только при наличии действительно нового типографического уровня, который используется несколькими компонентами.

Не создавать отдельную переменную для каждого уникального CSS-класса.

Основной принцип:

> Компоненты выбирают семантический тип текста, а реальные размеры задаёт общий файл `typography.css`.
