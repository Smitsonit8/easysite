# Рефакторинг системных настроек — дизайн

## Цель

Сделать настройки модуля `sporina.easysite` единым расширяемым механизмом: одна декларация определяет хранение, дефолт, валидацию, доступность шаблонов и отображение в административной панели.

## Границы и совместимость

- Публичные ключи настроек остаются без изменений.
- Сохраняются режимы компонента `render` и `configure`.
- Сохраняются AJAX-действия `apply`, `reset` и `remember-section`, их имена и форматы ответов.
- Настройки хранятся в разрезе сайта.
- Рефакторинг не изменяет разметку клиентской части сайта, кроме появления шаблона административной панели настроек.

## Архитектура

### Settings

Новый сервис `Sporina\EasySite\Settings` размещается в `lib/settings.php` и использует D7 API `Bitrix\Main\Config\Option`.

Сервис отвечает только за:

- объявление каталога настроек;
- получение безопасных значений;
- применение и сброс настроек;
- нормализацию входных данных;
- формирование данных для панели;
- проверку существования шаблонов.

Компонент `sporina:system.settings` остаётся тонким адаптером HTTP: проверяет права и sessid, вызывает сервис и формирует ответ или результат шаблона.

### Единый каталог

Каждая настройка объявляется ровно один раз в каталоге `Settings::getDefinitions()`. Декларация содержит:

- `key` — сохранённый ключ Bitrix Option;
- `category` — раздел панели;
- `type` — `select`, `checkbox` или `color`;
- `default` — автоматическое значение по умолчанию;
- `label` — ключ локализации;
- `values` — статический набор допустимых значений, если применимо;
- `template` — правило поиска шаблона компонента, если значение выбирает шаблон.

При добавлении нового блока разработчик добавляет одну декларацию: сервис автоматически использует её для чтения, валидации, сброса и рендеринга поля. Дополнительные списки дефолтов или allowlist не создаются.

## Поведение

### Автоматические значения по умолчанию

`getAll()` проходит по каталогу. Для каждой настройки сервис читает Option с её `default`. Если сохранённое значение отсутствует, не проходит валидацию или ссылается на отсутствующий шаблон, возвращается значение `default`. Некорректное значение не записывается автоматически: это исключает неожиданную мутацию данных при простом чтении.

`reset()` удаляет Options только для ключей из каталога, после чего `getAll()` немедленно вернёт декларативные дефолты.

### Валидация и шаблоны

Статические поля проверяются относительно `values`; цвет — регулярным выражением `#RRGGBB`. Для шаблонных полей допустимы только значения из их декларации, для которых в установленном шаблоне сайта существует `template.php`.

Правило шаблона включает базовый путь и имя выбранного шаблона. Путь вычисляется относительно `SITE_TEMPLATE_PATH` во время выполнения, поэтому проверяется установленный шаблон, а не только исходники модуля. При недоступности файловой системы безопасно используется дефолт.

### Панель настроек

Шаблон компонента получает категории и поля, построенные из каталога. Он выводит поля циклом, включая доступные варианты только после проверки существования шаблонов. Настройка категорий и полей не дублируется в шаблоне.

Состояние активной категории продолжает храниться в сессии. Существующий фронтенд-контракт сохранится: отправляются `settings`, действие и sessid.

### D7-стиль

Для Options используется `Bitrix\Main\Config\Option`. Компонент применяет `Bitrix\Main\HttpResponse`-совместимый путь для статусов и буфера, не меняя наблюдаемый JSON-контракт. Глобальные объекты остаются только в тех местах, где этого требует API компонента Bitrix (`$USER`, `$APPLICATION`).

## Ошибки и безопасность

- Запись доступна только администраторам и только с валидным sessid.
- Незнакомые ключи игнорируются; недопустимое известное значение приводит к 400.
- Ошибки инфраструктуры не раскрываются клиенту: возвращается 500 с общим сообщением.
- Неправильное значение в Option не ломает рендеринг сайта: применяется дефолт.

## Тестирование

Тесты проверяют, что:

- существует единственный каталог и в нём сохранены все существующие ключи и дефолты;
- компонент не содержит дублирующих `DEFAULTS`/`ALLOWED_VALUES`;
- все настройки панели поступают из `Settings`;
- шаблонные варианты описаны правилами существования;
- D7 `Option` используется для чтения, записи и сброса;
- существующие компонентные режимы, AJAX-действия, проверка прав и sessid сохранены.

Дополнительно выполняются `php -l` для добавленных и изменённых PHP-файлов и `node --test tests/system-settings.test.mjs`.

## Вне рамок

- Миграция или переименование существующих ключей.
- Автоматическая очистка старых некорректных Options при чтении.
- Переработка других компонентов, не использующих `sporina:system.settings`.
