# sporina.easysite

Модуль **1С-Битрикс: Управление сайтом** для быстрого развёртывания корпоративного сайта («сайт-визитка») с готовым шаблоном **Sporina Easy Site**, структурой разделов, демо-данными в инфоблоках и веб-формами.

**Идентификатор модуля:** `sporina.easysite`  
**Версия:** см. `install/version.php`  
**Мастер установки:** `sporina:easy_site`

## Возможности

- Установка модуля копирует в проект:
  - шаблон сайта `sporina_easy_site` в `/bitrix/templates/`;
  - мастер в `/bitrix/wizards/sporina/easy_site/`;
  - вспомогательные файлы в `/bitrix/php_interface/` (`constants.php`, `form_handler.php`) и при необходимости дописывает подключения в `init.php`.
- После установки модуля администратор запускает **мастер** (`wizard_install.php`), который может:
  - создать или привязать сайт;
  - развернуть публичную часть (страницы, меню, include-области);
  - назначить шаблон и тему оформления;
  - создать типы инфоблоков и импортировать XML с демо-контентом (по выбору);
  - создать веб-формы «Заказать» и «Купить» с нужными полями.

## Требования

- **1С-Битрикс:** редакция с поддержкой стандартного мастера решений (типично «Бизнес», «Малый бизнес» и выше — уточняйте по вашей лицензии).
- **Обязательные модули ядра:** `main`, `iblock`.
- **Рекомендуется:** модуль `form` (веб-формы) — без него создание форм в мастере и обработчики в `form_handler.php` не будут работать.

## Установка модуля

1. Скопируйте каталог модуля в корень установки Битрикс:

   `bitrix/modules/sporina.easysite/`

   (в репозитории лежит **содержимое** модуля; папку `sporina.easysite` создайте в `bitrix/modules/` и поместите в неё файлы из корня репозитория).

2. В админке откройте **Marketplace → Установленные решения → Модули** (или **Настройки → Настройки продукта → Модули**) и установите модуль **Sporina: Сайт-визитка** (`sporina.easysite`).

3. После успешной установки на экране появится кнопка запуска мастера. Либо вручную откройте:

   `/bitrix/admin/wizard_install.php?lang=ru&wizardName=sporina:easy_site`

   (не забудьте передать корректный `sessid` при работе из браузера с авторизацией).

## Мастер установки сайта

Имя мастера в системе: **`sporina:easy_site`**. Описание шагов задаётся в `install/wizards/sporina/easy_site/.description.php`.

Типовой сценарий шагов:

1. Выбор сайта (при полной установке).
2. Выбор шаблона **Sporina Easy Site**.
3. Выбор темы оформления.
4. Настройки сайта (название, телефон, копирайт, мета-теги и т.д.).
5. Установка данных (структура, инфоблоки, формы, файлы).
6. Завершение.

Сервисы мастера перечислены в `install/wizards/sporina/easy_site/site/services/.services.php`: блок **main** (сайт, файлы, шаблон, тема, меню, формы) и блок **iblock** (типы и импорт XML).

## Инфоблоки и коды

Типы инфоблоков создаются скриптом `site/services/iblock/types.php`. Коды типов:

| Код типа            | Назначение (по смыслу модуля)   |
|---------------------|----------------------------------|
| `advertising_bannerss` | Рекламные баннеры             |
| `cards_info`        | Карточки информации              |
| `news_and_changes`  | Новости и изменения              |
| `services`          | Услуги                           |
| `products`          | Товары                           |

Импорт из XML (`site/services/iblock/import.php`) создаёт инфоблоки с символьными кодами:

- `advertising_bannerss`
- `cards_info`
- `news_companii`
- `schedule_changes`
- `services`
- `products`

Файлы XML лежат в `install/wizards/sporina/easy_site/site/services/iblock/xml/<язык>/`.

## ЧПУ (urlrewrite)

Правила ЧПУ для компонентов `bitrix:news` (новости, изменения, услуги, товары) задаются в двух местах:

### 1. Шаблонный файл (копируется на сайт при установке)

**`install/wizards/sporina/easy_site/site/public/ru/urlrewrite.php`**

Этот файл копируется в корень сайта мастером установки. Содержит базовые правила для разделов `/novosti-kompanii/`, `/izmeneniya-v-raspisanii/`, `/uslugi/`, `/tovary/`.

### 2. Генерация при работе мастера

**`install/wizards/sporina/easy_site/site/services/main/files.php`** (массив `$arNewUrlRewrite`)

Мастер динамически добавляет правила через `CUrlRewriter::Add()`, учитывая `WIZARD_SITE_DIR` — каталог сайта (например, `/dd/`). Это позволяет работать ЧПУ на сайтах, установленных не в корень, а в подкаталог.

### Структура правил

Для каждого раздела создаётся **пара правил**:

| Назначение | CONDITION | RULE | SORT |
|-----------|-----------|------|------|
| Детальная страница | `#^SITE_DIR.section/([^/]+?)/\??(.*)#` | `ELEMENT_CODE=$1&$2` | 90 |
| Список | `#^SITE_DIR.section/\??(.*)#` | `&$1` | 100 |

- **SORT=90** (высокий приоритет) — перехватывает URL с символьным кодом элемента: `/dd/novosti-kompanii/kakaya-to-novost/`
- **SORT=100** (низкий приоритет) — срабатывает, если элемент не найден, и показывает список: `/dd/novosti-kompanii/`

> ⚠️ **Важно:** `RULE` для детальной страницы **обязательно** должен содержать `ELEMENT_CODE=$1`, иначе компонент `bitrix:news` не сможет отобразить детальный просмотр. Пустой `RULE` — частая причина ошибки «404» на детальных страницах новостей.

## Веб-формы

Создаются в стадии `create_forms.php` (см. `site/services/main/create_forms.php`):

| SID          | Назначение        |
|--------------|-------------------|
| `ORDER_FORM` | Заказ / заявка    |
| `BUY_FORM`   | Покупка / заказ товара |

При удалении модуля формы с этими SID удаляются (см. `UnInstallForms()` в `install/index.php`).

## Настройки модуля (опции)

В процессе работы мастера и шаблона используются опции `COption` для сайта (`sporina.easysite`, привязка к `SITE_ID`), в том числе:

- `install_demo_data` — ставились ли демо-данные;
- `use_site_template` — использование шаблона сайта;
- `wizard_installed` — мастер уже отрабатывал для сайта;
- `template_converted` — служебный флаг при копировании/конвертации шаблона.

## PHP-интерфейс: `constants.php` и `form_handler.php`

После `InstallFiles()` в `/bitrix/php_interface/` попадают:

- **`constants.php`** — вспомогательные функции и константы с ID инфоблоков по символьному коду и ID веб-форм по SID (используются в шаблоне и обработчиках).
- **`form_handler.php`** — логика подстановки данных из сессии в поля форм при отправке (например, название услуги/товара).

В существующий `init.php` модуль добавляет строки:

```php
require_once($_SERVER["DOCUMENT_ROOT"]."/bitrix/php_interface/form_handler.php");
require_once($_SERVER["DOCUMENT_ROOT"]."/bitrix/php_interface/constants.php");
```

При **удалении** модуля эти `require` удаляются из `init.php`, файлы `form_handler.php` и `constants.php` из каталога `php_interface` удаляются (если они принадлежали модулю).

## Удаление модуля

Стандартное удаление через список модулей. Выполняется:

- отмена регистрации модуля;
- удаление шаблона `/bitrix/templates/sporina_easy_site`;
- удаление мастера `/bitrix/wizards/sporina/easy_site`;
- удаление указанных типов инфоблоков и форм `ORDER_FORM` / `BUY_FORM`;
- правка `init.php` и удаление скопированных файлов `php_interface`, как описано выше.

**Внимание:** публичная часть и сами инфоблоки с контентом, созданные мастером в структуре сайта, могут не удаляться автоматически полностью — ориентируйтесь на бэкап проекта.

## Публикация на GitHub

В каталоге модуля уже инициализирован Git и сделан первый коммит (ветка `master`). Дальше:

1. На [GitHub](https://github.com/new) создайте **пустой** репозиторий (без README, без `.gitignore`), например `sporina.easysite`.
2. В корне проекта выполните (подставьте свой URL):

   ```text
   git remote add origin https://github.com/<ваш-логин>/sporina.easysite.git
   git push -u origin master
   ```

   При использовании SSH:

   ```text
   git remote add origin git@github.com:<ваш-логин>/sporina.easysite.git
   git push -u origin master
   ```

3. Чтобы имя и email автора коммитов совпадали с аккаунтом GitHub, один раз настройте `git config user.name` и `user.email` (глобально или только в этом репозитории) и при необходимости сделайте `git commit --amend --reset-author`.
